## 1. Project Overview

### What it does

**EDU-GAP** (branded **EduBridge** in the UI) is a learning platform that helps students learn from study material, get unstuck on doubts, and practice what they know — while giving teachers visibility into each student's progress.

The platform combines three learning loops into one experience:

| Loop | What it does | Why it matters |
|------|--------------|----------------|
| **AI Doubt Solver** | Students upload a PDF / paste a URL / type raw text, then chat with a Gemini-powered assistant that answers *from those sources*. | Source-grounded answers are more trustworthy than generic LLM responses. |
| **Adaptive AI Quiz** | A multiple-choice quiz is auto-generated from the student's recent chat history (LangGraph agent). | Quizzes stay tied to what the student was actually studying. |
| **Progress & Analytics** | Quizzes are graded, summarized, and weak topics are extracted via LLM. Teachers see aggregated analytics for their students. | Closes the feedback loop — students see what to revise; teachers see who needs help. |

### Problem it solves

Generic AI tutors hallucinate. Generic LMSs lack personalization. EDU-GAP sits in the middle: a student uploads their actual course material, has a conversation about it, gets a quiz from that conversation, and the system remembers what they keep getting wrong.

### Target users & roles

The platform has two roles, chosen at sign-up:

| Role | Capabilities |
|------|--------------|
| **Student** | Upload learning sources, chat with the AI tutor, take quizzes generated from their chat history, view their own progress dashboard, delete completed quizzes. |
| **Teacher** | Browse the list of students (filter by class, search by name/username/email), drill into a specific student to see their progress summary, weak topics, and recent quizzes. |

There is **no admin role** in the current codebase **[Inferred]** — only `student` and `teacher` are enforced by the `User` schema enum (`user.model.js`).

### Data flow — a typical authenticated request

1. **UI event** — e.g. student clicks "Take Quiz" on `StudentDashboard`.
2. **Navigation** — `useNavigate()` pushes `/student/quiz` (handled by `ProtectedRoute`).
3. **Auth check** — `ProtectedRoute` reads Redux `auth.user`. If absent or role mismatch, redirects to `/signin` or `/`.
4. **API call** — `axios.post('http://localhost:5000/api/quiz', {}, { withCredentials: true })`. The cookie set during login travels with the request.
5. **Express middleware chain** — `cors` → `cookie-parser` → `helmet` → `express.json()` → router → `protect` middleware.
6. **`protect` middleware** — reads `req.cookies.token`, verifies with `JWT_SECRET`, loads user from MongoDB (or falls back to a minimal stub if Mongo is offline), attaches `req.user`.
7. **Controller** — `createQuiz` reads the user's in-memory chat history via `getHistory(userId)`, calls `generateQuizQuestions({ chatSummary })` (LangGraph → Gemini), sanitizes the LLM output, persists a `Quiz` document, returns it.
8. **UI update** — the response is dispatched into local React state, the page navigates to `/student/quiz/:quizId` for the quiz UI.
9. **Subsequent steps** — submit answer, complete quiz, refresh analytics — all follow the same pattern with cookie auth.

### Key design patterns

| Pattern | Where it's used |
|---------|-----------------|
| **MVC-ish controller-per-resource** | `controllers/*.js` export named async functions; routes wire HTTP verbs to them. |
| **REST-style resource routing** | `/api/auth`, `/api/quiz`, `/api/chatbot`, `/api/analytics`, `/api/users`. |
| **JWT in httpOnly cookie** | `authController` issues a 7-day JWT, sets it as a cookie (`httpOnly`, `sameSite: 'strict'`); `protect` middleware verifies it on every protected request. |
| **In-memory fallback** | When `MONGO_URI` is absent, `connectDB()` returns `false` and the app continues — auth uses a `Map` of users (`memoryUsers`), chatbot data uses `chatbotStore` (always in-memory). **[Inferred — explicitly a graceful-degrade design choice in `config/db.js`]** |
| **State management: Redux Toolkit (slices)** | Single `auth` slice holding `{ user, isAuthenticated, isLoading }`. No global store for domain data — most page-local data uses `useState`. |
| **LLM orchestration via LangGraph** | Three small graphs (`generateQuizQuestions`, `analyzeCurrentQuiz`, `generateProgressSummary`) share a Zod-validated `invokeJson` helper. The chatbot uses a `retrieve → generate` graph. |
| **RAG via in-memory vector store** | Source chunks are embedded with `GoogleGenerativeAIEmbeddings` and stored in a per-user `MemoryVectorStore` (`chatbotStore.js`). Similarity search feeds Gemini. |
| **Role-based route guards** | `ProtectedRoute allowedRoles={['student']}` wraps the `<Route>` children; `teacherOnly` middleware gates teacher-only routes. |
| **Field-scoped client validation** | `SignIn` / `SignUp` validate, set per-field errors, clear them on input change — exactly as the project conventions require. |

### Auth mechanism

- **Sign-up**: `POST /api/auth/signup` — bcrypt-hashes the password, stores user, issues JWT, sets `token` httpOnly cookie (7-day expiry).
- **Sign-in**: `POST /api/auth/login` — bcrypt-verifies password, issues JWT, sets cookie.
- **Session bootstrap**: `GET /api/auth/current-user` (called from `App.jsx`'s mount effect) re-validates the cookie and hydrates the Redux `auth.user` slice. If absent or invalid, the slice is cleared.
- **Sign-out**: `POST /api/auth/logout` — clears the cookie.
- **Route guarding**: `protect` middleware reads `req.cookies.token`, verifies it, loads the user from Mongo (or a minimal stub if Mongo is offline). `teacherOnly` middleware enforces role.
- **Cookie flags**: `httpOnly: true`, `sameSite: 'strict'`, `secure: false` **[Inferred — current setting is suitable for local dev over HTTP; flip `secure: true` for HTTPS production.]**

| Field | Type | Notes |
|-------|------|-------|
| `student` | ObjectId → `User` | **unique** — one analytics record per student. |
| `recentQuizzes` | `[ObjectId → Quiz]` | Up to **3 most-recent completed quizzes**. Older ones are deleted in `completeQuiz` and `deleteQuiz` controllers. |
| `overallProgressSummary` | String | LLM-generated summary across recent quizzes. |
| `weakTopics` | `[String]` | Recurring weak topics across recent quizzes. |
| `createdAt`, `updatedAt` | Date | |

### Relationships

```
User (1) ──────── (many) Quiz
  │                     ▲
  │                     │ recentQuizzes
  ▼                     │
StudentAnalytics (1) ───┘
  (one per student)
```

- A student has many quizzes; each quiz references exactly one student.
- A student has zero or one `StudentAnalytics` document (upserted on first quiz completion).
- `StudentAnalytics.recentQuizzes` is a many-side reference array capped at 3 entries.
- `Quiz.questions` is an embedded subdocument array (not a separate collection).

> The `User` collection holds both `student` and `teacher` records. There is **no separate Teacher model**.

### What's NOT in the database

- **Chat history** is stored in-process in `chatbotStore.js` (a `Map<userId, store>`). It does **not** persist across server restarts.
- **Uploaded source files / chunks / vector store** are also in `chatbotStore.js`. **Not persisted** [Inferred — the store is a plain in-memory Map].
- This means: if the server restarts, all chat history, sources, and embeddings are lost. Quizzes and analytics survive (they're in Mongo).

## 5. API Reference

Base URL: `http://localhost:5000` (matches `client/src/main.jsx` `export const serverurl`).

All authenticated routes require the `token` cookie set by `/api/auth/login` or `/api/auth/signup`. Send requests with `axios`'s `withCredentials: true`.

### Auth — `/api/auth`

| Method | Path | Auth | Purpose | Request body | Response (200/201) |
|--------|------|------|---------|--------------|---------------------|
| `POST` | `/api/auth/signup` | public | Register a new user | `{ name, username, email, password, role, class }` | `{ message, user: { id, name, username, email, role, class } }` |
| `POST` | `/api/auth/login` | public | Sign in | `{ email, password }` | `{ message, user: { id, name, username, email, role, class } }` |
| `GET` | `/api/auth/current-user` | required | Hydrate session on app mount | — | `{ user: { id, name, username, email, role, class } }` |
| `POST` | `/api/auth/logout` | required | Clear cookie | — | `{ message: "Logout successful" }` |

### Quiz — `/api/quiz`

All routes require `protect` (any logged-in user, but quiz operations are scoped to a student).

| Method | Path | Auth | Purpose | Request body | Response |
|--------|------|------|---------|--------------|----------|
| `POST` | `/api/quiz` | student | Create a quiz from current chat history. Reads in-memory history, calls LangGraph `generateQuizQuestions`, sanitizes, persists. | `{}` | `{ success, message, quiz }` (status 201; 400 if no history; 422 if LLM fails to generate ≥2 valid questions) |
| `GET` | `/api/quiz/:id` | student | Fetch a quiz by id (must be the owner). | — | `{ success, quiz }` |

| `POST` | `/api/quiz/:quizId/complete` | student | Finalize quiz: score, AI analysis (`analyzeCurrentQuiz`), trim to 3 most-recent completed, regenerate progress summary, upsert `StudentAnalytics`. | `{}` | `{ success, message, result: { score, totalQuestions, strengths, weakTopics, overallProgressSummary, overallWeakTopics } }` |

All routes require `protect`. All state is per-user, in-memory.

| Method | Path | Auth | Purpose | Request body | Response |
|--------|------|------|---------|--------------|----------|
| `GET` | `/api/chatbot/sources` | required | List sources uploaded by the current user. | — | `{ sources: [{ id, type, name, meta }] }` |
| `POST` | `/api/chatbot/reset` | required | Drop all sources, chunks, history, vector store for the user. | `{}` | `{ message, sources }` |

| `DELETE` | `/api/chatbot/sources/:id` | required | Remove one source and its chunks. | — | `{ sources }` |
| `POST` | `/api/chatbot/chat` | required | Send a question. | Method | Path | Auth | Purpose | Query params | Response |
|--------|------|------|---------|--------------|----------|
| `GET` | `/api/users/students` | **teacher** | List all students. Supports `?search=<regex>` (matches name/username/email) and `?className=<class>` (or `"all"`). Sorted by name asc. | `search`, `className` | `{ success, count, students: [{ _id, name, username, email, className }] }` |

### Standard error envelope

Errors are returned as `{ success: false, message: "..." }` or `{ message: "..." }` (auth routes omit `success`). The frontend reads `error.response.data.message`.

### Route guards (frontend)

- `App.jsx` mount effect: `GET /api/auth/current-user` → `dispatch(setUser | clearUser)`.
- `ProtectedRoute allowedRoles={['student']}`: renders an `<Outlet/>` if user is authenticated and role matches; otherwise `<Navigate>` to `/signin` (unauthenticated) or `/` (wrong role).
- `GuestRoute` (wraps `/signin` and `/signup`): if already authenticated, redirect to `/student` or `/teacher` based on role.

### End-to-end user flows

#### Flow 1 — Student asks a question and takes a quiz

1. **Sign up** at `/signup`. Choose role `Student`, enter class as digits. Submit → Redux `auth.user` set, redirected to `/signin`.
2. **Sign in** at `/signin`. JWT cookie set by server. Redirected to `/student`.
3. From the dashboard, click **Ask Questions** → `/student/chatbot`.
4. **Upload a source**: open the upload modal, pick a PDF or paste a URL, submit.
   - Client: `POST /api/chatbot/sources` (multipart). Server: extracts text, chunks it (1200 chars), indexes into the user's `MemoryVectorStore` with `GoogleGenerativeAIEmbeddings`.
5. **Ask a question** in the composer. Hit send.
   - Client: `POST /api/chatbot/chat` with `{ message }`.
   - Server: runs `retrieve` (similarity search, k=4) → `generate` (Gemini with system prompt + last 8 history turns + retrieved context) → returns `{ answer, sourcesUsed, history }`.
6. **Repeat** step 5 a few times to build chat history.
7. From the dashboard, click **Take Quiz**.
   - Client: `POST /api/quiz` (empty body). Server: pulls chat history, calls `generateQuizQuestions` (LangGraph → Gemini with strict JSON output validated by Zod), sanitizes, persists a `Quiz` doc. Client navigates to `/student/quiz/:quizId`.
8. **Answer questions** one at a time.
   - Client: `POST /api/quiz/:quizId/question/:questionIndex/answer` with `{ answer }`. Server persists `selectedAnswer` and `isCorrect`, advances `currentQuestionIndex`.
9. On the last question, click **Complete Quiz**.
   - Client: `POST /api/quiz/:quizId/complete`.
   - Server: scores the quiz, runs `analyzeCurrentQuiz` (LLM extracts `strongTopics` / `weakTopics`), trims to 3 most-recent completed quizzes, runs `generateProgressSummary` (LLM summarizes + lists recurring weak topics), upserts the user's `StudentAnalytics`.
   - Client shows a completion popup with the score.
10. Navigate to **Analytics** at `/student/analytics`.
    - Client fires two parallel requests: `GET /api/analytics` and `GET /api/analytics/quizzes`. Renders progress summary, weak topics, and a list of quiz cards.

#### Flow 2 — Teacher inspects a student

1. **Sign up** as `Teacher` (a teacher can sign up at `/signup` like any user) and sign in.
2. From `/teacher`, click **View Student Progress** → `/teacher/student` (the student list).
3. The page calls `GET /api/users/students?search=...&className=...` (teacher-only middleware), shows searchable/filterable student cards.
4. Click a student card → `/teacher/student/:studentId`.
5. The page calls `GET /api/analytics/teacher/student/:studentId/analytics`. Renders the student's name, recent quizzes (without correct answers), overall progress summary, and weak topics.

#### Flow 3 — Sign-out

1. Click **Logout** on a dashboard.
2. Client: `POST /api/auth/logout` (cookie cleared server-side). Client dispatches `clearUser`, navigates to `/signin`.

### Environment variables

`server/.env` — copy from `server/.env.example`:

| Key | Required? | Example | Notes |
|-----|-----------|---------|-------|
| `PORT` | no | `5000` | Express port. Default 5000. |

| `JWT_SECRET` | **yes** | `<random-secret>` | Signs the 7-day JWTs. Use a long random string in production. |
| `GOOGLE_API_KEY` | **yes (for AI features)** | `<google-ai-studio-key>` | Used by `gemini-2.5-flash` and `gemini-embedding-001`. Without it, chatbot says "Gemini is not configured" and quiz creation fails. |
| `GOOGLE_EMBEDDING_MODEL` | no | `gemini-embedding-001` | Override the default embedding model. |

### ⚠️ Known limitations & issues

- **Missing `server/index.js`** — the file is referenced by `npm run dev` / `npm start` but is not present in the repo. The README's API section assumes a conventional Express entry point is wired up; please confirm or add it.
- **`controllers/quiz.controller.js` filename mismatch** — `routes/quiz.routes.js` imports from `"../controllers/quiz.controller.js"`. Other controllers use the singular (`authController.js`, `user.controller.js`, `analytics.controller.js`). If the file isn't named exactly `quiz.controller.js`, the import will fail.
- **Teacher Dashboard navigation target** — `TeacherDashboard.jsx` calls `navigate("/teacher/students")` but `App.jsx` registers `/teacher/student` (singular). Clicking the card likely 404s until reconciled [Inferred].
- **No tests** — no test runner is configured for either client or server. Suggested additions: Vitest + React Testing Library (client), Vitest + Supertest (server).
- **In-memory chatbot data** — chat history, sources, chunks, and vector store are lost on every server restart. For real persistence, swap `chatbotStore.js`'s `Map` for a persistent vector store (e.g., MongoDB Atlas Vector Search) and add a `ChatHistory` model.
- **`secure: false` cookie flag** — fine for local HTTP dev; flip to `true` for any HTTPS production deployment.
- **Quiz `origin: "weak_topics"`** is modeled in the schema but no UI generates those quizzes today [Inferred].
- **Rate limiter / input validators** — dependencies installed (`express-rate-limit`, `express-validator`, `helmet`) but `helmet` and `cookie-parser` are not confirmed wired up in the missing `index.js`; `express-rate-limit` and `express-validator` similarly unused in source [Inferred].
- **Chatbot URL extraction** uses `fetch` + regex HTML strip rather than the installed `cheerio` library. Functional but fragile.
